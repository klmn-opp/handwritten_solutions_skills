0.1 最终目标
构建一个开源的、可个性化训练、可持续学习的神经手写作业生成系统。
最终使用流程：
用户提供题目，格式可以是文字、图片或 PDF。
Agent 自动识别题目，完成解题与独立校核。
Agent 产生准确、精炼、具有必要解题步骤的英文 Markdown / LaTeX。
系统根据数学结构与个人书写习惯规划页面。
Personal Handwriting Engine 生成符合用户个人风格的英文、数字和数学符号墨迹。
Handnote / MathText 负责可靠的数学结构与页面排版。
系统验证内容、公式结构、页面边界和字体来源。
输出完整 PDF、逐页 PNG、可编辑解答、质量报告与可复现记录。
每道顶层大题对应一页；小题保留在所属大题页面内。默认 A4 白纸，支持自定义背景。
正常使用时不应要求用户手工选择字形、拼接页面或反复调整公式位置。
0.2 个性化训练目标
用户可以不断提供新的真实笔迹，包括：
单字符与数学符号。
自然英文单词、句子和完整书写行。
历史手写作业 PDF。
真实数学公式与连续推导。
可选的数位笔在线轨迹。
对生成结果的个人偏好评价。
训练系统需要逐渐学习：
个人稳定的字形结构。
自然字形变化。
相邻字母之间的联系与连笔。
整词共享的倾斜、尺度和笔画特征。
一行文字的书写节奏。
数学符号与结构笔画的个人习惯。
完整页面的组织方式。
最终生成器必须具有超出固定字形复制的泛化能力。
给定训练中未出现过的文字或数学表达式，也应能够产生内容正确、个人风格一致且具有合理自然变化的书写结果。
0.3 研发基本原则
产品可靠性与生成模型研究并行，但分别验收。
稳定产品可以使用确定性字形和结构排版。
神经模型只负责已经证实有价值的生成部分。
不能为了提高自然度而牺牲文字或数学正确性。
不能让持续训练影响正式出稿。
研究失败应保留完整证据，不能通过重新命名实验声称取得进展。
RL 和 RSI 是后续能力，不是当前模型质量不足时的默认补救措施。
本次任务应实际推进开发、运行测试并交付产物，而不是仅重新整理 Roadmap。

这些实验形成了以下约束：
经验 A：重建成功不等于生成成功
模型在看到真实形态条件时能重建，不证明从文字与随机潜变量出发能正确生成。
训练重建与独立生成必须分别报告。
经验 B：字体约束与生成自由存在权衡
过强的字体约束会压缩变化；过弱的内容约束可能造成缺笔、重复、灰影或错误字符。
新模型必须同时评价字符身份、完整性、合理变化和个人相似性。
经验 C：有效监督比原始页数重要
已有大量历史 PDF，但可训练样本数量远少于原始页数。
不同版本的样本、裁剪和衍生图不能简单相加。
必须按实际可靠标签、独立来源与内容覆盖评价数据量。
经验 D：缩小任务往往更有效
当前可靠成果来自局部墨迹生成、真实几何测量和确定性数学结构。
未来模型应逐步扩展到词和行，不应立即重新尝试无约束的整页图像生成。
经验 E：一个实验必须回答一个具体问题
不能再次无期限进行“扩大模型—增加损失—延长训练—换一种先验”的循环。
每次实验必须具备：
可检验的假设。
明确的对照基线。
固定数据划分。
有界计算预算。
预先定义的成功与失败标准。
实际最终页面的效果验证。

3.1 数学与英文采用不同可靠性策略
英文可以逐步使用更自由的局部和连续神经生成。
数学必须保留语义结构约束：
公式解析和二维布局不交给不受约束的图像生成器。
数字、变量和符号可使用个人墨迹。
分数、根号、矩阵、上下标和括号由结构系统确定位置与范围。
神经模型不能擅自添加、删除或改变运算符。
不支持的结构应拒绝或明确回退。
3.2 生产与训练严格解耦
普通 CPU 用户不应需要 CUDA 或 PyTorch 训练环境。
建议支持：
font-cpu

hybrid
已验收的个人数学和可用神经墨迹组成的混合后端。
neural-context-experimental
后续研究中的上下文神经生成后端。
具体 CLI 名称可依据已有实现调整，但能力与验收状态必须清晰区分。
3.3 Profile 不只是一个字体文件
未来一个 Profile 应能够包含：

不得覆盖旧 Profile 以模拟升级。

执行任务

测试分为两个体系。
Render-only

外部字体回退。
结构笔画。
越界与裁切。
无法自动校验的公式人工复核状态。
必须检验未在旧七页中出现的符号和结构。
独立测试管理
将开发集、回归集与新 Holdout 分离。
此前已经曝光的测试页面不能再次作为新的独立泛化证据。

3.3 主动补充有价值的监督
优先发现：

M4 — Context-Aware Personal Neural Handwriting
目标
突破当前最重要的技术限制：
神经网络虽然能够生成局部墨迹，但字符之间仍主要依靠组合器拼接，没有充分学会真实连续书写。
本阶段要证明模型能够利用上下文产生更自然的完整词和英文行。
4.1 固定现有主力骨干
保留 v0.10.21 canonical-conditioned-ink/1 作为可靠神经基线。
不能因为新模型训练次数更多，就直接替换它。
首先复现当前局部生成及其整页表现。
4.2 研究目标
建议采用分层思想：
Content / Characters
        +
Word or Line Context
        +
Personal Style Representation
        +
Stochastic Variation
        ↓
Context-Aware Ink Generator
        ↓
Verified Word / Line Ink
模型应考虑：
相邻字母。
字符处于词首、词中或词尾。
整词共享的倾斜与尺寸。
连字和起收笔关系。
个人风格的一致性。
同一字符的合理变化。
字符身份和墨迹完整性。
4.3 三组最小受控对照
A：当前局部模型
独立字符生成，再按已有 Handnote Composer 排版。
B：共享词级状态
同一单词中的局部生成使用共享风格状态，避免字符独立采样造成突变。
C：真实完整词监督
使用已经核验的完整词图、相邻字符关系及词内墨迹训练上下文模块。
三组应尽可能保持相同基础数据、输出条件、采样预算和评估内容。
C 必须真正使用连续真实墨迹作为训练监督，不能只把单字模型循环调用并重新命名。
4.4 训练模型选择
允许保留现有局部生成器，并新增轻量上下文模块。
只有在明确证明当前架构无法表达目标时，才重新评估更复杂的生成架构。
不要直接重新启动此前失败的整词 CVAE、GAN 或扩散路线，除非提出并验证了不同于旧实验的具体技术假设。
保留一次仅验证少量候选的有界实验设计。
4.5 重点解决训练—生成条件差距
单独检查：
真实条件重建。
训练文本上的独立采样。
未见词汇上的独立采样。
潜变量响应。
字形记忆与最近邻相似度。
真实上下文是否产生可观察的贡献。
不要用高质量重建代替新内容生成。
4.6 评价方式
固定真实单词、句子和作业片段。
比较：
字符正确性。
缺笔和断笔。
连笔自然度。
词内比例。
行内一致性。
个人风格相似性。
变化多样性。
到训练样本的最近邻距离。
内容不合格的候选不能因为更自然而胜出。
验收
在真正未见过的内容上，新模型必须比当前神经基线提供明确的整体收益，且不增加已确认的内容错误。
必须有作者本人或经过适当校准的独立评价支持，而不能只凭训练损失、Dice、OCR 或轮廓距离。
如果多次有界对照都失败，冻结结果并给出 No-Go，继续使用旧骨干。
M5 — 神经个性化训练与可靠混合推理
目标
让用户可以利用自己的历史笔迹，训练一个可用于新文字的个人生成模型，并安全地接入实际作业生成。
执行任务
5.1 监督个性化
以已验证语料为核心，研究：
个人风格表示。
多次采集之间的风格稳定性。
不同字符共享的个人笔画规律。
上下文条件。
新增样本的持续适配。
少量样本类别的稳健训练。
不得默认 LoRA 适合所有模型。
根据实际生成器结构选择是否使用参数高效训练。
5.2 数据扩展训练
沿用已有数据父版本与 checkpoint 继承校验。
保留：
旧数据完整性。
新数据来源。
Checkpoint 祖先关系。
优化器状态。
数据采样权重。
真实与字体辅助样本比例。
模型权重变化。
独立验证结果。
新增数据后需要检查模型是否遗忘旧字符。
5.3 可靠推理
神经输出需要通过质量门禁。
建议：
对指定内容生成候选。
检查字符覆盖、边界和完整性。
使用识别器发现可疑字符。
必要时进行独立转写或人工复核。
不满足要求时回退至可靠的个人字体。
记录具体回退原因与来源。
OCR 不得被当作完全可靠的内容真值。
数学保持结构约束。
5.4 Profile 发布
训练完成生成 Candidate Profile。
Candidate 应同时包含神经权重、个人字形、数学符号、布局配置及来源信息。
只有在内容、个人风格和完整作业回归中通过后，才能进入可发布状态。
验收
用户能够增量提供真实作业，并通过明确的训练流程得到新的模型候选。
模型必须在未见过的文字上发挥作用，而不是只重新生成训练词汇。
从输入新题到完成 PDF 的整个过程不依赖开发者手工预处理。
普通 CPU 用户继续拥有完整可用的非神经后端。
M6 — Personal Preference Optimization / RL
启动前提
只有 M4/M5 得到了内容可靠、具有合理多样性的神经生成器后，才能进入本阶段。
如果模型仍持续漏字或断笔，本阶段保持 No-Go。
目标
让用户的个人审美评价直接优化生成模型，而不再只是选择六种预设渲染动作。
6.1 建立偏好数据集
同一内容生成多个候选。
用户盲评：
哪个更像本人。
哪个更自然。
哪个更工整。
哪个连笔更流畅。
哪个整体比例更协调。
哪个公式书写更自然。
保留 neither、tie、无法判断等选项。
先进行内容校核，再对有效结果进行风格比较。
不要让不同内容的候选直接进行个人相似性比较。
6.2 先做无需参数更新的基线
首先验证 Best-of-N 是否能够显著改善最终结果。
如果单纯选择已有候选已经能够满足要求，不应无理由引入复杂 RL。
6.3 真正训练偏好模型
根据生成器结构评估：
Pairwise Preference Learning。
DPO 类偏好优化。
可适配的生成模型偏好优化方法。
必要时才研究在线 RL。
如果采用参数训练，必须证明生成器参数实际更新。
不能把候选重排序、调整字体概率或简单 bandit 称为神经生成模型强化学习。
6.4 防止奖励投机
必须防止模型通过以下方式提高代理评分：
越来越接近某一个训练字形。
降低字形多样性。
牺牲细笔和内容完整性。
改变文字间距来欺骗视觉评价器。
学习 OCR 的识别偏差。
记忆人工偏好集中出现过的少量词。
应设置独立内容门禁、风格 Holdout、重复检测和模型回滚。
验收
在内容准确性不下降的前提下，新模型在独立未见文本上的本人风格盲评中取得稳定提升。
效果必须优于未进行偏好训练的生成器和 Best-of-N 基线，才有理由继续投入 RL。
如果没有可重复收益，保留结果并停止扩展。
M7 — Controlled Recursive Self-Improvement
目标
建立一个能够利用历史经验持续改善个人笔迹模型的自动研究闭环。
这里的 RSI 是受约束的模型与训练流程持续改进，不是无限制的自主代码修改。
7.1 自动发现薄弱点
系统定期分析：
低覆盖字符。
反复断裂的笔画。
特定连字错误。
数学符号缺失。
对新词泛化较差的类别。
用户频繁不满意的生成形态。
特定背景或排版下的问题。
7.2 Active Learning
优先从已有真实历史 PDF 中寻找对应样本。
若找不到，生成最小补采任务。
例如：
需要 5 个真实 f 词中间连写样本
而不是让用户每次重新抄写整套字母表。
补采请求应能说明为什么需要这些样本，以及准备改进哪一项能力。
7.3 自动实验流程
发现失败
    ↓
分析原因
    ↓
确定需要的数据或模型修改
    ↓
建立实验假设
    ↓
创建独立实验分支
    ↓
训练候选模型
    ↓
固定 Benchmark 检查
    ↓
新 Holdout / 人工验收
    ↓
发布候选或回滚
自动系统可以提出并执行低风险的隔离实验，但不能直接覆盖生产模型。
7.4 数据污染保护
不允许将生成模型自身输出未经核验地加入真实用户样本库。
真实样本、用户确认数据、推测轨迹和合成数据必须分层标记。
不得通过反复生成合成笔迹并自我训练来伪造数据增长。
7.5 自动发布门禁
以下行为需要明确用户批准：
替换正式默认 Profile。
发布新生产模型。
覆盖历史训练数据。
向外部服务上传个人作业。
修改已冻结的最终评估协议。
进行可能不可逆的资产操作。
验收
系统能够通过新真实数据和独立评价形成持续改进的候选模型，并且在多轮迭代中保护既有能力。
失败的候选能够完整回滚。
所有自动改进必须可追踪、可复现、可停止。
M8 — 开源发行、可迁移 Profile 与长期维护
目标
使项目不仅能服务当前作者，也能让普通用户使用默认字体，或逐步训练自己的个人笔迹。
执行任务
8.1 默认开箱即用
普通用户可以：
安装 Skill。
使用内置默认手写 Profile。
输入题目并生成 PDF。
自定义纸张。
查看渲染与错误报告。
无需 GPU 或个人训练资料。
默认字体如果使用作者真实笔迹，必须确保分发授权与隐私范围明确。
8.2 个性化 Studio
用户可以：
导入历史手写作业。
查看 OCR/HTR 结果。
修正标签。
积累个人数据。
采集缺失字形。
构建个人字体。
在可用 GPU 上训练候选模型。
对比版本。
发布或回滚 Profile。
8.3 私有数据与许可
项目必须分别审查：
源码许可。
第三方依赖许可。
字体及字形资产许可。
训练数据使用权限。
模型权重再分发权限。
个人作业、原始笔迹、私有权重及身份信息默认不进入公开 Git 和发行包。
不同作者的数据应相互隔离。
8.4 可迁移性
实现 Profile 的导出、导入、版本校验、兼容性检查和回滚。
训练阶段依赖 GPU，但经过发布的模型可以根据实际支持情况提供 CPU、GPU 或预渲染配置。
不得承诺所有神经模型都具有可接受的 CPU 推理性能，必须实际测量。
验收
新的普通用户能在干净环境中完成安装、出稿和基础 Profile 使用。
拥有个人数据和受支持 GPU 的用户能够进行增量训练，并安全管理自己的模型版本。
Part IV — 全阶段统一 Benchmark 和质量门禁
4. 质量指标体系
所有阶段必须区分以下评价目标。
维度
核心问题
Content Fidelity
文字是否准确完整
Math Fidelity
数学语义和二维结构是否正确
Glyph Identity
每个字符是否可辨认
Stroke Integrity
是否存在断笔、缺笔和异常墨迹
Personal Similarity
是否像作者本人
Natural Variation
是否存在合理而非机械的变化
Context Coherence
字符、单词与行是否协调
Layout Quality
页面是否自然、清晰和工整
Generalization
是否适用于未见词和新作业
Reproducibility
模型、数据、参数和结果是否可追溯
不得把这些指标合并成一个不透明的“真实性百分比”。
5. 建议的验收机制
5.1 内容门禁
任何被确认存在缺字、错字或数学结构错误的候选，不得因视觉效果好而获得生产准入。
未知或自动验证不足的内容应标记待复核。
5.2 作者盲评
研究候选应与当前最强可用基线比较，而不是只与早期失败模型比较。
建议每次主要候选评估至少包含数十组成对样本，并预注册内容选择、评价维度与通过标准。
可以先以至少 50 组独立比较作为正式风格评价的目标规模。
是否采用 60%、65% 或其他胜率门槛，应在评估前结合样本数量和置信区间确定；不能事后根据结果调整。
5.3 新内容泛化
必须包含未参与训练和模型选择的真实文字、公式和整页作业。
评估使用的字体、Profile、数学结构和文本条件要保留完整来源。
5.4 多样性和记忆
固定相同内容，使用多个随机种子生成。
同时检查：
输出之间差异。
输出到训练字形的最近邻距离。
输出到个人真实未见样本的相似程度。
字符身份是否稳定。
是否出现明显模式坍缩。
不能仅凭像素不同宣称具有自然生成能力。
5.5 最终页面
所有生成模型研究最终都必须落到实际英文句子、数学表达式与完整作业 PDF 中。
孤立字形和短词测试只能作为诊断，不能替代成品质量验收。
Part V — Codex 执行与工程管理要求
6. 自主推进规则
本计划应作为长期总 Roadmap 执行。
Codex 应遵循阶段顺序，但允许独立工作流并行：
产品稳定化不必等待新神经模型。
语料清洗可以与产品测试并行。
研究模型不能绕过质量门禁进入生产。
RL 与 RSI 不能提前绕过生成模型准入条件。

需要本人确认真实笔迹标签。

需要本人完成风格盲评。

需要对外分享或授权私人数据。

9. 实验预算和停止规则
默认每个新的神经研究假设只允许先进行有限数量的受控对照。
优先进行小规模真实实验，确认方向有价值后再扩大。
如果连续实验只改善训练代理指标，却没有改善未见内容或完整作业，应停止扩展。
不得通过以下方式声称进步：
增加训练步数。
增大模型参数。
增加测试数量。
选择更好看的随机种子。
只展示重建结果。
只展示少数成功词。
删除失败案例。
通过更多字体复制降低形状距离。
修改 Holdout 后重新宣布独立成功。
对于无法证明有效的神经路线，应明确 No-Go，并保护现有最优模型。

Part VI — 最终验收与完成定义
12. Level 1 — Reliable Handwritten Solutions
用户提供一份新数学作业后，系统能自动：
读取。
解题。
校核。
排版。
使用个人笔迹。
验证数学结构。
输出 PDF/PNG。
不需要用户手工拼接、调整公式或运行研究脚本。
普通 CPU 环境可用。
这是 v1.0 的交付目标。
13. Level 2 — Learned Personal Handwriting
在未见过的英文和数学表达式中：
具有用户稳定的个人书写特征。
合理地生成训练样本中没有直接出现的字形变化。
字母间关系与词内比例自然。
不依赖逐个复制字库中的固定轮廓。
数学结构仍然准确。
多次生成具有合理差异。
实际作者盲评优于现有最强基线。
这是核心神经研究目标。
14. Level 3 — Continual Personal Handwriting Studio
用户可以持续提供新笔迹。
系统能：
增量整理与核验。
发现缺失覆盖。
主动请求有价值的补样。
训练新模型候选。
利用作者偏好优化。
在独立测试中检验进步。
发布、切换和回滚 Profile。
保留完整训练历史。

用真实个人数据学习稳定的书写风格，用可靠的数学结构保证内容准确，通过神经生成获得自然变化，通过持续训练与个人反馈不断改善最终页面。
任何新技术都应围绕这一目标证明自身的实际收益。
保留 Handnote 的工整、内容控制和数学可靠性，让神经网络专注于其无法直接提供的个人书写变化与连续性。
最终实现一个可靠、自然、可训练、可持续进化，并且普通用户也能够实际使用的 Handwritten Solutions Agent Skill。
