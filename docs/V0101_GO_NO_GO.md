## 新网络与真实CUDA更新

`aligned-content-ink/1`，144709参数，卷积编码器、沿行扩张卷积与特征跳接解码器，输入/输出64×512。
输入是指定文字的个人字体参考，输出是学习生成的完整SDF墨迹区域；无原始像素直拷贝输出路径。
确定性训练和推理同一路径，本轮主动不宣称随机多样性、跨作者风格分离或数学符号安全生成。

RTX5060 Laptop 8151MiB，Torch2.7.1+cu128，固定seed1103、lr .0003、batch4。
先1500次字体辅助预热，再从同一预热权重启动三臂；每批3真实+1字体，均2000次更新，固定最后一步，不选Holdout最优。

## 失败、修复与限制

1. 内容教师最初默认tokenizer加入BOS，但真实冻结checkpoint生成协议是EOS起始、正文、EOS。
   4个真实字体参考测试证实错误序列增加损失；改为`content-then-eos/no-predicted-bos/1`。
   两个旧run保留为failed，错误链累计1500个持久化更新，不作科学比较；未保存的后续更新数不确定。
   修正后从同一预热权重重新完整训练2000步；恢复检查拒绝跨标签协议复用旧优化器。
2. 第一条长命令被约120秒时限终止。后续使用有PID、日志和状态的监督后台流程，全部正常结束。
3. 冻结后发现一张浅蓝真实参考的灰度最低154，旧深色阈值无法处理。首评估run保留failed。
   仅评估显示增加带记录的线性对比度回退，原图/训练预处理/已冻结权重不变；没有丢弃该测试条目。
4. HTR环境无CPU pydantic：改成隔离worker，只用JSON/Torch；没有给CPU安装Torch。
5. 最终无神经数学替换；新模型也没有真实随机风格、自由行布局或作者自然度验收。

为什么仍不理想：词级对齐只能消除部分词距差异，不能对齐同词内部的笔画、字宽、斜度和基线；
逐像素目标仍有平均重影风险。内容教师改善可辨读性，却没有约束真实墨迹的干净度，不能排除利用灰墨带满足识别器的捷径。
这些是结合消融和图像的解释，未证实唯一机制。171真实训练区域、仅14条较长英文，仍限制自然上下文学习；
数据也存在不同书写大小与用笔，模型没有显式条件区分局部风格。增加同一模型步数并不能证明能解决这些问题。

## 下一步决策

- Go：继续从已有PDF收集可靠完整短词/词组，优先同词多次真实书写及更长英文，先审计覆盖再谈扩大模型。
- 下一次有限试验应固定短词范围，研究词内软对齐或序列内容对齐、独立墨迹清晰度约束；不能无限提高字体像素权重。
- 对同页其他真实区域建立可追溯风格条件，训练时不得把目标图偷偷作为推理输入；之后才评估共享随机风格和连续行。
- 内容、清晰度都达到Handnote对照且作者视觉偏好成立，才扩大长度与训练量。保持公式由Handnote/MathText处理。
- 本轮21新区域已打开，后续只能作历史测试；新架构需要另封区域，最终仍缺全新文档级泛化证据。
- 目前不要求用户重抄字母表；现有PDF仍可继续清洗。作者可先评6组匿名页面，尤其辨别“更像本人”与“仅更模糊”。
