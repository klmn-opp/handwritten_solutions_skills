# M2.3 — Qualified personal CPU release candidate

Implementation candidate:1.0.0rc2, isolated branch `feature/m23-qualified-personal-cpu`.
This document records implementation scope; actual installed evidence is required
before marking the lifecycle accepted. Production activation/publication is separate.

## Hypothesis and baseline

The verified deterministic personal CPU recipe can run through the ordinary Job
workflow without research modules or manually cached word images. The missing product
boundary is evidence-based local admission, not a new neural model. FrozenRC1/source884
and final privatev5 (word-gap1.1448) provide the page baseline on Linux and macOS.
New runtime code must preserve those actual outputs and inherit no arbitrary ZIP
admission claims. No glyph or model update is proposed by this change.

## Implemented boundary

`profiles qualify-ink` validates typed, hash-bound evidence and stores an immutable
local snapshot. Evidence binds exact Profile/recipe/wheel/source/lock/Handnote code,
actual OS/architecture/Python/Pillow engine features, clean installation receipts,
complete verified Jobs/PDF/PNG, independent mathematics review and author consent.
Each platform has its own actual prior page for the scoped word-gap adjustment.
The author's accepted base and prescribed increment are distinguished from a new
visual approval; Mac review is by Agents, not falsely attributed to the author.

`profiles publish-ink` separately publishes a qualified version in the local store.
It does not change default settings. Explicit activate/rollback changes the local
selection. Ordinary `font-cpu` accepts that published personal version only while
its current build/environment and evidence still match. Imports always remain
inactive candidates, including exports from a qualified store. Authority is not a
Profile asset or a portable ZIP field. Existing plain-font behavior remains intact.

These local records validate evidence consistency; they are not an attestation
against a malicious owner able to rewrite the entire store. Reviewed local pages
are finite evidence, not proof of universal symbol coverage. Every new Job still
runs semantic, geometry, contact and output checks; unsupported structures remain
explicit rejections or source-recorded fallbacks.

## Verification and current gate

Synthetic contract tests exercise wrong/stale bindings, actual wheel code identity,
platform feature drift, scoped-consent limits, locks, interrupted publication and
recovery, inactive import and normal Job dispatch. They are not Mac or handwriting
quality evidence. Existing CPU/Profile/Job regression remains required.

Pending actual source freeze: canonical RC2 wheel/sdist/Skill; fresh Linux3.12/3.13
and native Mac3.12/3.13 installation; per-platform exact page comparison to RC1;
real evidence bundle; isolated qualify→publish→ordinary render→activate→rollback
and export/reimport. A changed runtime needs its own installation evidence.

Production main/latest/default, historical data/weights and sealedC are protected.
No new neural training, external publication or production activation occurs here.
