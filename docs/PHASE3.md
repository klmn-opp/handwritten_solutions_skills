# Phase 3 · 作业质量与可移植性

`hwsol verify --job <dir> --pixels` 会用本机锁定的 PDFium 重绘最终 PDF 的每一页，与交付 PNG 的 RGB 像素逐一比对。常规 verify 仍检查文件摘要、原题编号、原始材料、解答、数学复算和文档尺寸。跨机器重放逐像素比较时应使用相同的依赖和平台。

已在 Linux 实测美国 Letter、横向 A4、方纸，以及包含极限、分式、根式、求和、均值、向量和矩阵的单题作业。每页的数学回退字形可在报告中查看。另有故意交换两页 PNG 后同步更新摘要的反例，像素核验能指出错页。个人字形测试保留九个真实不同的合成轮廓，验证相同种子重放和不同种子产生的像素差异。过长解答的失败仍保留逐次排版记录。

同一页重复字形按轮廓和线性变换复用边界计算。白纸直接用最终导出的页面检验可见性，有纹理的背景仍单独比对底图。候选字体评估从训练记录中的副本渲染，避免上游字体缓存持有待发布文件。归档路径在所有系统上都拒绝 Windows 保留设备名及不能移植的文件名。

## 五题 CPU 基准

在项目根目录运行 `uv run --locked python scripts/benchmark.py --output out/benchmark.json`。每次使用新的私有数据目录及字体缓存，测一次首次导入与渲染、两次同进程重复渲染。每轮包含五页、PDF/PNG 写入和常规验证。峰值为进程至该轮为止的最大驻留内存。这里记录单机观察值，首次启动和短跑计时会波动。

## 平台验收

仓库 CI 覆盖 Ubuntu、macOS 和 Windows，每个平台分别运行 Python 3.12、3.13 的锁定安装、测试、打包和独立 wheel 安装。独立运行环境用中文输出路径渲染并逐像素验证五题作业，检查无 torch 和 pytest。可选 MarkdownToHandwrite 环境由 Linux 本地另行测试。实际执行状态见[实施记录](IMPLEMENTATION_STATUS.md)。苹果和 Windows 原生结果需由对应 runner 产生。
